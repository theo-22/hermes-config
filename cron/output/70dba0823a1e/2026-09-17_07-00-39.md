The new entries cluster hard around one theme: **App Intents pass local tests but fail at system-level discovery**. Worthwhile findings:

- **AppShortcutsProvider MUST live in the main app target, not an SPM package** — Apple DTS confirmed (High confidence). Two separate forum threads + a DTS reply all say the same thing: static SPM packages compile fine but the Shortcuts daemon can't find the provider. [Thread](https://developer.apple.com/forums/thread/759160)

- **`appintentsmetadataprocessor` export failure blocks system indexing silently** — build succeeds, intents vanish from Shortcuts with no error. Check build logs for metadata generation failures. [Blog](https://www.adamrussell.com/appintent-not-showing-in-shortcuts-app)

- **MainActor isolation in `perform()` triggers cold-start background execution failures** — intents drop out when the app is suspended. [Analysis](https://drobinin.com/consulting/app-intents-siri/making-your-app-work-with-the-new-siri/)

- **Accented app names break App Shortcuts phrase recognition** — system indexing fails, code compiles fine. [Forum](https://developer.apple.com/forums/thread/838210)

- **AppIntentsTesting passes out-of-process but doesn't verify system indexing daemons** — Apple docs confirm the disconnect between test framework and real invocation. [Docs](https://developer.apple.com/documentation/AppIntentsTesting/testing-your-app-intents-code)

**Bottom line:** If any of your app's App Intents disappeared from Shortcuts after a build, check (1) target membership — provider must be in the main app, not SPM; (2) build log for metadata processor errors; (3) accented characters in the app name. Those three explain most "tests pass but nothing works" cases.
